# ROI pHash監視 + 条件付き翻訳 実装案（高速化・自動翻訳最適化）

1. **概要（1–3行）**
   複数ROIを登録し、ROIごとの pHash 変化を監視して変化時のみ OCR を実行する。
   OCR結果の文字数/行数/信頼度に基づき翻訳可否を判定し、既存キャッシュを最大活用する。

2. **ゴール / 非ゴール**
   **ゴール**

   * 変化があったROIだけOCR・翻訳することで高速化
   * OCRノイズや短文を翻訳対象から除外し、無駄な翻訳を減らす
   * 既存キャッシュ/前回結果を活用して安定動作

   **非ゴール**

   * すべてのフレームを保存する録画用途
   * 全OCR結果を必ず翻訳する挙動
   * 高度な字幕検出/シーン理解の導入

3. **前提・仮定**（不確実性の扱いを明確化）

   * ROIはユーザが複数指定できる（既存ROI拡張または新規設定）
   * `PhashService` と `OcrDiffService` を流用できる
   * 既存の翻訳キャッシュ（CacheRepository）を維持する

4. **現状整理**（現行挙動、関連モジュール、既存制約）

   * 現在は単一ROIで OCR → diff → 翻訳というフロー
   * pHash は全体ROIで変化検知し、翻訳スキップに利用
   * 翻訳はキャッシュ優先で実行される

5. **提案アーキテクチャ**

   ### コンポーネント構成

   * `RoiProfile`（新規）
     * ROI矩形・pHash閾値・翻訳判定閾値（文字数/行数/信頼度）
   * `RoiWatchState`（新規）
     * 直近pHash・最終OCR結果・最終翻訳時刻
   * `RoiWatcher`（新規 or Pipeline内ロジック拡張）
     * ROIごとの pHash 変化検知とOCRトリガー

   ### データフロー / シーケンス

   1. ROIリストを取得
   2. ROIごとに pHash を計算し、変化判定
   3. 変化したROIのみOCR実行
   4. OCR結果のしきい値判定
   5. 翻訳（キャッシュ優先）→ オーバーレイ更新

   ### 既存パターンへの整合

   * `PipelineOrchestrator` で「ROIリスト→OCR→翻訳」へ拡張
   * 既存キャッシュ/正規化/差分ロジックは再利用

6. **インターフェース設計**

   ### 設定項目（案）

   * `EnableMultiRoi`（複数ROI有効化）
   * `RoiProfiles`（ROI配列 + 個別閾値）
   * `MinOcrChars` / `MinOcrLines` / `MinOcrConfidence`
   * `RoiPhashThresholdBase`（ROIサイズで補正する基準）

   ### 判定ロジック（例）

   * 文字数 >= `MinOcrChars`
   * 行数 >= `MinOcrLines`
   * 平均信頼度 >= `MinOcrConfidence`
   * 同一テキスト（normalized）かつ pHash差分小 → 翻訳スキップ

7. **実装手順（ステップ分割）**

   ### Step 1: ROI複数化のデータ構造
   * `SerializableRect` の配列化 or 新規 `RoiProfile` を追加
   * UIで複数ROI設定を受け付ける導線（簡易は設定JSON直編集でも可）

   ### Step 2: ROIごとの pHash 監視
   * ROI単位の pHash 保存と比較
   * ROIサイズに応じて閾値を補正

   ### Step 3: OCR/翻訳判定ゲート
   * OCR結果の文字数/行数/信頼度を集計
   * 閾値以下は翻訳をスキップ

   ### Step 4: キャッシュ活用
   * 既存の `CacheRepository` を優先
   * 直近翻訳と同一なら再翻訳を回避

8. **非機能要件チェック**

   * **性能**：ROIごとにOCRを最小化、翻訳回数を削減
   * **セキュリティ**：画像データの保存は行わない
   * **可観測性**：ROIごとのトリガー/スキップ理由をログ出力
   * **互換性**：単一ROIモードは従来通り維持

9. **リスクと緩和策**

   * **pHashだけでは小さな字幕変化に弱い**
     * 緩和: ROIサイズに応じて閾値を可変化
   * **閾値チューニングが必要**
     * 緩和: 設定可能にしてログでフィードバック
   * **複数ROIの同時OCR負荷**
     * 緩和: 変化ROIのみ実行、必要なら間引き

10. **影響範囲**（変更ファイル候補・移行・ドキュメント更新）

* 変更候補
  * `Models/AppSettings.cs`
  * `Services/PipelineOrchestrator.cs`
  * `Services/PhashService.cs`
  * `UI/MainWindow.xaml(.cs)`（ROI管理UI）
* ドキュメント更新
  * 本ドキュメント

11. **Definition of Done**（完了条件のチェックリスト）

* [ ] ROI複数設定が可能
* [ ] ROIごとの pHash 変化検知が動作
* [ ] OCR結果の閾値判定で翻訳が制御される
* [ ] キャッシュ活用による翻訳スキップが機能
* [ ] 従来の単一ROI動作が維持される

## 12. **ユーザUI案**

### 12.1 ROI管理パネル

* **ROI一覧**（リスト表示）
  * 表示列: 名前 / 有効 / pHash閾値 / 最終更新時刻
  * 右側に「選択ROIを表示」トグル

* **操作ボタン**
  * 追加（矩形選択）
  * 複製
  * 削除
  * 並び替え（上/下）

### 12.2 ROI編集パネル（選択ROI）

* **基本情報**
  * 名前
  * 有効/無効
  * ROI矩形（X/Y/W/H）

* **pHash判定設定**
  * 基準閾値（スライダー）
  * ROIサイズ補正ON/OFF

* **翻訳判定ゲート**
  * 最小文字数
  * 最小行数
  * 最小信頼度（平均）

### 12.3 全体設定（共通）

* 複数ROI有効化チェック
* OCRトリガー方式
  * pHash変化時のみ
  * 常時OCR（デバッグ用）
* 翻訳判定ゲートのデフォルト値

### 12.4 既存UIとの整合

* 既存のROI選択UIは「ROI追加」として再利用
* 既存の単一ROI設定は「ROI #1」に自動移行

### 12.5 UX補足

* ROIごとに色分け表示
* pHash変化時に該当ROIを短時間ハイライト
* OCR/翻訳スキップ理由をログに明示
