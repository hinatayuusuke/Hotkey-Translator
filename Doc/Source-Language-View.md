

**案1: 同一枠内2段表示（推奨）**
- 原文を上、訳文を下で同じ枠に表示
- 枠は下方向に自動拡張（必要時のみ）
- メリット: どの文の対訳か迷わない、実装が比較的シンプル
- デメリット: 小さい枠だと高さ不足

**案2: 追加枠を近傍配置**
- 元枠は原文、訳文は右→下→左→上の順で空き位置探索して追加枠
- 衝突最小の位置を自動選択
- メリット: 元枠を崩さない、長文でも表示しやすい
- デメリット: レイアウトロジックが重くなる

**案3: ハイブリッド**
- まず案1を試す
- 高さ上限超過・他枠衝突が大きい場合のみ案2へフォールバック
- メリット: 普段は安定、厳しいケースだけ逃がせる

実装としては**案3**が最もバランスが良いです。  
最初の実装ルールはこれで十分です。

1. 同一枠2段を基本にする  
2. 自動拡張は最大 `元高さの2.0〜2.5倍` まで  
3. 超えたら追加枠へ切替  
4. 文字サイズは原文を訳文の `0.85〜0.9` 倍  
5. 背景は原文/訳文で薄くトーンを分ける（同系色）

**Hybrid表示アルゴリズム（原文＋訳文）**

1. 入力
- `baseRect`（OCR座標）
- `srcText`, `trText`
- `canvasRect`
- `placedRects`（既に確定した表示枠）
- `config`（下記の閾値）

2. 前処理
- 空白正規化（改行→`\n`、連続空白圧縮）
- 表示テキスト生成  
  原文: `srcText`  
  訳文: `trText`
- 基準フォント計算（既存フォントフィッタを利用）

3. Stage A: 同一枠2段表示を試行
- 枠内を上段（原文）/下段（訳文）に分割
- 必要高さを計測し、足りなければ下方向へ枠拡張
- 拡張上限は `baseRect.height * maxExpandScale`（推奨 `2.3`）
- 拡張後に `canvasRect` 内へクランプ
- スコア判定  
  `scoreA = overlapPenalty + overflowPenalty + resizePenalty`
- 条件を満たせば採用  
  `overlapRatio <= 0.15` かつ `overflow == 0`

4. Stage B: 追加枠表示へフォールバック
- 原文は `baseRect`（またはStage Aで確定した上段）に維持
- 訳文用 `trRect` を候補生成  
  優先順: 右 → 下 → 左 → 上 → 右下 → 左下
- 各候補でサイズ計測し、必要なら幅を再調整
- 各候補を採点  
  `scoreB = 1000*outOfBounds + 500*overlapArea + 1.0*distance + 0.5*leaderLineLen`
- 最小スコア候補を採用

5. Stage C: それでも置けない場合
- 訳文を省略表示（先頭N文字 + `…`）
- 原文枠右上に「+」バッジを付ける
- ホバー/トグルで全文表示（任意）

6. ちらつき抑制
- 座標スナップ（整数化）
- 前フレーム採用レイアウトを優先  
  新レイアウトとの差分が閾値未満なら前回維持
- 閾値例: `dx+dy < 6px` かつ `dw+dh < 8px`

7. 推奨パラメータ
- `maxExpandScale = 2.3`
- `minGap = 6px`
- `maxExtraBoxWidth = baseRect.width * 1.4`
- `srcFontScale = 1.0`
- `trFontScale = 0.9`
- `sameBoxOverlapLimit = 0.15`

```pseudo
layout(item):
  A = trySameBox(item)
  if A.accept: return A
  B = tryExtraBox(item)
  if B.accept: return B
  return compactFallback(item)
```

**概要**

Phase 1 は「同じ OCR 矩形の中、またはその下方向への限定拡張だけで、原文と訳文を2段表示する」実装です。追加枠探索はやらず、座標の安定性と実装の単純さを優先します。

**ゴール**

- 原文と訳文の対応関係が一目で分かる
- OCR座標から大きく外れない
- Hook/WPF の両方で同じレイアウト思想を使える
- ちらつきを最小化する

**非ゴール**

- 右や下に別枠を自動探索して配置する
- 他枠との複雑な衝突回避を行う
- ホバー全文表示やトグルUIを入れる

**推奨レイアウト仕様**

1. ベース矩形
- 入力は既存の `baseRect(x, y, w, h)`
- この矩形を表示の基準にする
- X/Y は整数スナップする

2. 表示構成
- 上段に原文
- 下段に訳文
- 同一背景枠の中で上下に積む
- 背景色は1つでよい
- 区切りは細いギャップだけで十分。明示線は Phase 1 では不要

3. 高さの扱い
- まず `baseRect` の高さ内に収まるか試す
- 収まらない場合のみ、下方向へ拡張する
- 拡張上限は `min(baseRect.h * 2.0, canvasH * 0.18)` を推奨
- 上限を超える場合は省略モードへ落とす

4. フォント
- 既存のフォントフィット結果を基準にする
- 主表示側を `1.0`
- 従表示側を `0.85` 前後
- 初期推奨は:
  - `SourceAboveTranslation`: 原文 `0.90`, 訳文 `1.00`
  - 原文確認重視なら逆でもよい
- 最小フォント下限は既存下限に合わせる
- 無理に2段を維持するために極端に小さくしない

5. パディング
- 外側パディングは小さめ固定
- 推奨:
  - 左右 `2`
  - 上下 `1`
- 原文と訳文の段間ギャップは `2〜4px`

6. 折り返し
- どちらも同じ有効幅で折り返す
- 有効幅 = `rect.w - leftPad - rightPad`
- 原文・訳文それぞれ独立に必要高さを測る

**採用アルゴリズム**

1. 入力
- `baseRect`
- `srcText`
- `trText`
- `canvasRect`
- `previousLayout`
- `config`

2. 前処理
- 表示用だけ改行・空白を軽く正規化
- 空文字ならその段は非表示可能
- 両方空ならブロック自体を描かない

3. レイアウト試行
- `srcHeight = measure(srcText, srcFont, width)`
- `trHeight = measure(trText, trFont, width)`
- `neededHeight = topPad + srcHeight + gap + trHeight + bottomPad`
- `finalHeight = clamp(neededHeight, baseRect.h, maxExpandedHeight)`

4. 判定
- `neededHeight <= maxExpandedHeight` なら採用
- それ以外は省略モードへ移行

5. 省略モード
- 推奨は「訳文優先」
- 訳文を表示
- 原文は先頭短縮または非表示
- 省略されたことが分かるよう `...` を付ける
- Phase 1 では追加枠へ逃がさない

**ちらつき抑制**

- X/Y/W/H を整数スナップ
- 前回レイアウトとの差分が小さい場合は前回を維持
- 推奨閾値:
  - `abs(dx)+abs(dy) < 4`
  - `abs(dh) < 6`
- テキストが同じで高さ差が微小なら再レイアウトしない

**描画ルール**

- 1ブロック = 1背景矩形
- 原文描画位置:
  - `x + leftPad, y + topPad`
- 訳文描画位置:
  - `x + leftPad, y + topPad + srcHeight + gap`
- クリップは最終矩形内に限定
- ROI枠やデバッグUIより下、通常オーバーレイテキストとして描く

**既存実装への当て方**

- WPF 側:
  - 1つの Overlay item を内部2段に分ける
  - 現在のフォントサイズ算出をベースに、原文/訳文へ倍率適用
- Hook 側:
  - OverlayV2 の1ブロックに「2段テキスト」を載せるか
  - または `src/tr` を持つ表示専用ブロック構造に拡張
- Phase 1 では「追加枠生成」は入れない

**最小実装方針**

1. 表示モード `SourceAboveTranslation` を追加
2. レイアウト計算関数を1つ追加
3. 高さの限定拡張だけ許可
4. 上限超過時は訳文優先の省略表示
5. 前回レイアウト維持で揺れを抑制

このPhase 1なら、ゲームOCRオーバーレイとして重要な「対訳の分かりやすさ」「座標の安定」「実装リスクの低さ」を優先できます。追加枠探索はこの段階では入れない方が良いです。
