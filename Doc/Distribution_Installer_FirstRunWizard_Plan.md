# Distribution Installer + First-Run Wizard Plan

1. **概要（1–3行）**
- 本計画は、配布方式を「インストーラー（Setup.exe）」中心に統一し、初回起動時にSetupウィザードで実行環境を確定する実装案である。
- 推奨はハイブリッド方式（インストール責務はSetup.exe、アプリ設定責務は初回ウィザード）とする。
- CTranslate2 は破棄前提とし、導入対象から完全に除外する。

2. **ゴール / 非ゴール**
### ゴール
- 一般ユーザー向けに失敗しづらい配布導線（インストール→初回設定→利用開始）を提供する。
- 依存関係の初期不整合（OCR/翻訳バックエンド、モデル、GPU設定）をウィザードで可視化し、即時に修正できるようにする。
- 本体更新・アンインストール・ショートカット作成など、運用に必要な基本機能をインストーラーで提供する。

### 非ゴール
- CTranslate2 関連機能の維持・移行（対象外）。
- 初回設定のクラウド同期。
- すべての依存（巨大モデル含む）をインストーラー本体へ同梱すること。

3. **前提・仮定**
- 配布ターゲットは Windows デスクトップ利用者。
- 既存アプリは settings.json ベースで設定管理している。
- OCR/翻訳バックエンドは実行環境差異（GPU/CPU、ドライバ、権限）の影響を受ける。
- 初回ウィザードはアプリ内実装（WPF）で提供可能。

4. **現状整理（配布形式比較）**
- **インストーラーのみ**
  - 長所: インストール/アンインストール/更新導線が明確。
  - 短所: 環境差異に応じた柔軟な初期設定が弱い。
- **実行後Setupウィザードのみ（ポータブル配布中心）**
  - 長所: 実行時環境に合わせた調整がしやすい。
  - 短所: 配布管理（導入先、更新、削除）が利用者任せになりやすい。
- **ハイブリッド（推奨）**
  - 長所: 配布管理の安定性と初期設定の柔軟性を両立。
  - 短所: 実装面が2層（インストーラー + ウィザード）になる。

5. **提案アーキテクチャ**
### 5.1 推奨構成
- 配布本線: Setup.exe（Inno Setup / NSIS いずれか）
- 初回起動: アプリ内 FirstRunSetupWizard
- 補助配布: 上級者向け Portable.zip（任意）

### 5.2 役割分担
- インストーラー責務
  - インストール先作成、ショートカット、アンインストール登録
  - 必須ランタイム前提チェック（不足時の案内）
  - アプリ本体配置
  - LlamaCpp バイナリ（`llama-server` など実行ファイル）を同梱配置
- 初回ウィザード責務
  - 言語、OCRエンジン、翻訳優先度、APIキー、GPU/CPU方針
  - OCR/翻訳の選択構成に応じたモデル導入（PaddleOCR / PaddleOCR-VL / LlamaCpp）
  - バックエンド疎通テスト（短時間、Paddle/WinRT/LlamaCpp）
  - 設定保存と結果サマリ表示

### 5.3 Python/uv 運用方針（推奨）
- Python 側コードはリポジトリ構成のまま同梱（フォルダ配布）。
- `uv` は「システム全体インストール」ではなく、アプリ配下に同梱してローカル実行する。
- 初回ウィザードでローカル仮想環境を作成し、`uv sync` で依存解決する。
- PaddleOCR / PaddleOCR-VL モデルはインストーラーへ同梱せず、初回ウィザードで選択構成に応じてダウンロードする。
- LlamaCpp モデルはインストーラーへ同梱せず、初回ウィザードで「ローカル翻訳」を選択した場合に `uv run <model_download_script>` でダウンロードする（容量/失敗率対策）。
- モデルダウンロード時は保存先を固定し、ハッシュ検証（または署名検証）を実施する。

### 5.4 CTranslate2 除外方針
- UI/設定/起動チェック/ドキュメントから CTranslate2 分岐を削除。
- 初回ウィザードの翻訳バックエンド候補に CTranslate2 を出さない。
- 互換読み込み時に旧 settings.json の CTranslate2 値は無視または移行警告のみ出す。

6. **インターフェース設計**
### 6.1 初回起動判定
- settings.json に SetupCompletedVersion（例: 1.0.0）を追加。
- 判定:
  - 値なし → 初回ウィザード起動
  - 値あり & 必須項目不足 → 修復ウィザード起動

### 6.2 ウィザード画面（案）
- Step 1: Welcome / 使用条件
- Step 2: Capture + OCR基本設定
- Step 3: 翻訳設定（ローカル/クラウド選択、優先度、APIキー）
- Step 4: 実行確認（疎通テスト）
- Step 5: 完了（保存内容サマリ）

### 6.3 エラー/バリデーション
- APIキー未設定は「スキップ可」だが、機能制限を明示。
- 疎通テスト失敗時は原因候補と再試行導線を提示。
- 設定保存失敗時はロールバックせず、再保存導線を優先。
- WinRT OCR を選んだ言語で利用する場合、`Language.OCR` Capability の有無を事前チェックする。
- 未導入時は「管理者権限が必要」「組織ポリシーで失敗する可能性」を明示し、導入スキップ導線も残す。
- LlamaCpp を利用する場合、以下を事前チェックする:
  - `llama-server` 実行ファイルの存在（同梱バイナリ）
  - モデルファイル存在（未選択時は「未使用で続行」を明示）
  - 起動後のHTTP/gRPC疎通
- LlamaCpp チェック失敗時は、Llamaを無効化して続行できる導線を提供する。
- PaddleOCR / PaddleOCR-VL を利用する場合、以下を事前チェックする:
  - 必要モデルの存在（未導入時は取得導線を提示）
  - モデル取得後の最小OCR疎通
- Paddle系モデル取得失敗時は、WinRT等の代替OCR導線または「後で再取得」で続行できるようにする。

### 6.4 EULA / ライセンス同意設計
- ウィザードStep 1で、アプリEULAと第三者ライセンス参照導線を提示する。
- モデル自動ダウンロードを行う前に、モデル提供元ライセンス/利用規約への同意チェックを要求する。
- 同意状態は設定へ保存し、未同意時は該当機能のダウンロード実行をブロックする。
- `NOTICE` / `THIRD_PARTY_LICENSES` を同梱し、インストール後も参照可能にする。
- LlamaCpp バイナリ再配布時は `llama.cpp` 側ライセンス条件を満たす配布物構成（LICENSE/NOTICE同梱）を必須とする。
- ローカル翻訳モデルはモデルごとのライセンスを一覧表示し、モデル単位で同意記録を保持する。

### 6.5 WinRT OCR Capability 導入（昇格PowerShell）
- 言語パック全体ではなく、対象言語の OCR Capability のみを導入対象とする。
- ウィザードから「OCRエンジンのみ導入」ボタンを提供し、押下時に管理者昇格した PowerShell を実行する。
- 実行コマンドは `Add-WindowsCapability -Online -Name Language.OCR~~~<lang-tag>~0.0.1.0` を基本とする。
- 実行前に、対象Capabilityの未導入確認・言語タグ妥当性・オンライン状態をチェックする。
- 実行前に注意ダイアログを表示し、以下へ同意した場合のみ実行する:
  - 管理者昇格が発生する
  - 企業管理端末では失敗し得る
  - ネットワーク接続が必要
- 実行結果はログとUIに表示し、成功後はCapability再チェックを自動実行する。

7. **実装手順（ステップ分割）**
- Step 1: 配布方針の固定
  - Setup.exe 本線 + Portable.zip サブの2系統に決定。
  - CTranslate2 を対象外として仕様明記。

- Step 2: First-run判定と状態管理
  - SetupCompletedVersion 導入。
  - 初回/修復ウィザード起動条件を実装。

- Step 3: SetupウィザードUI実装
  - 5ステップの最小構成を実装。
  - 翻訳設定で「ローカル翻訳（LlamaCpp）」選択導線を実装。
  - 途中離脱時の保存ポリシー（保存しない/部分保存）を固定。

- Step 4: 疎通テスト実装
  - OCR/翻訳の最小テストを1操作で実行。
  - LlamaCpp は「モデル既存時のみ」起動テスト（ポート疎通）を実行する。
  - 失敗時はログ・UIメッセージ両方に残す。

- Step 5: WinRT OCR導線実装（任意）
  - 選択言語に対する OCR Capability の有無を検出する。
  - 未導入時に「OCRエンジンのみ導入（管理者）」を提示する。
  - 昇格PowerShell実行、終了コード判定、再チェック、失敗時フォールバック案内を実装する。

- Step 6: Python依存とモデル導線実装
  - ローカル `uv` 実行で `.venv` を作成し、lock準拠で依存同期する。
  - OCR設定で PaddleOCR / PaddleOCR-VL が選択されている場合、必要モデルを取得する導線を実装する。
  - ローカル翻訳選択時は、LlamaCpp モデルを `uv run <model_download_script>` でダウンロードする導線を実装する。
  - Paddle系モデルは「必須/任意」を区分し、進捗表示・再試行・後回し導線を提供する。
  - ダウンロード完了後に LlamaCpp 起動テスト（モデル存在確認 + ポート疎通）を実行する。
  - モデルダウンロードは「任意ステップ + 進捗表示 + 中断/再試行」を実装。

- Step 7: インストーラー整備
  - インストール先、ショートカット、アンインストール、起動オプションを設定。
  - 署名・SmartScreen対策（可能ならコード署名）を組み込む。
  - LlamaCpp バイナリを同梱し、配置パスを起動設定へ反映する。
  - `uv` バイナリ、`NOTICE`、`THIRD_PARTY_LICENSES`、必要な再配布ライセンス文書を同梱する。

- Step 8: 旧設定互換とクリーニング
  - CTranslate2 由来設定の無視/警告処理。
  - ドキュメントとUI文言を最終更新。
  - Llama未設定/無効での起動パスを明示し、初回導線の文言を整備。

8. **非機能要件チェック**
- 運用性
  - 更新・再インストール・アンインストール手順が明確であること。
- 信頼性
  - 初回設定失敗時でもアプリが起動不能にならないこと。
- セキュリティ
  - APIキーは既存の保護方針に従い保存し、ログ出力しない。
- コンプライアンス
  - アプリEULA、第三者OSSライセンス、モデル利用規約への同意フローを分離し記録する。
- 性能
  - 初回ウィザードの疎通テストは短時間（体感数秒）で終了する設計にする。

9. **リスクと緩和策**
- Risk: 初回ウィザードが長く感じられて離脱される。
- Mitigation: 必須項目を最小化し、詳細設定は後で変更可能にする。

- Risk: 依存不備で疎通テストが失敗し、導入障壁になる。
- Mitigation: 原因候補を具体表示し、「後で設定」導線を残す。

- Risk: CTranslate2 除外で旧利用者が混乱する。
- Mitigation: 初回起動時に一度だけ移行メッセージを表示する。

- Risk: `uv` や第三者パッケージのライセンス条件を満たさず配布してしまう。
- Mitigation: リリース時にライセンス監査チェックリストを運用し、`THIRD_PARTY_LICENSES` を常に更新する。

- Risk: モデル利用規約未同意のままダウンロードが進む。
- Mitigation: 同意フラグがない場合はダウンロードUIを無効化し、同意取得を必須化する。

- Risk: 昇格PowerShell実行がポリシー/権限で失敗し、セットアップが停滞する。
- Mitigation: 失敗時はWinRT利用を必須化せず、手動導入手順と代替OCR導線を即時提示する。

- Risk: LlamaCpp モデル未配置や起動失敗で初回設定が完了できなくなる。
- Mitigation: Llama利用を必須化せず、「無効で続行」経路を常に提供する。

10. **影響範囲（変更ファイル候補・移行・ドキュメント更新）**
- MainWindow.xaml(.cs) または専用Window — First-run Wizard UI追加。
- ViewModels/* — ウィザード状態・検証ロジック追加。
- Models/AppSettings.cs — SetupCompletedVersion 等の初期化状態追加。
- Services/Settings/* — 初回判定・旧設定互換処理。
- installer/*（新規）— Setup.exe 定義スクリプト。
- Python runtime bundle（新規）— ローカル `uv` 実行基盤と依存同期スクリプト。
- Doc/* — 配布/初回設定ガイド更新。

11. **Definition of Done**
- [ ] Setup.exe で通常インストール/アンインストールが行える。
- [ ] 初回起動時のみSetupウィザードが表示される。
- [ ] 設定保存後、通常画面へ遷移し再起動しても再実行されない。
- [ ] 疎通テスト失敗時に原因案内と再試行導線が表示される。
- [ ] CTranslate2 が UI・設定・ウィザードから除外されている。
- [ ] 配布手順（Setup本線/Portable補助）がドキュメント化されている。
- [ ] ローカル `uv` 実行で依存同期が完了する。
- [ ] EULA / 第三者ライセンス / モデル規約の同意フローが動作する。
- [ ] WinRT OCR対象言語で、OCR Capability 未導入時の昇格導入フローが動作する。
- [ ] LlamaCpp の存在確認・起動疎通テスト・失敗時フォールバックが動作する。
- [ ] PaddleOCR / PaddleOCR-VL で必要モデル導入フローと失敗時フォールバックが動作する。
- [ ] ローカル翻訳未選択時はモデルDLを実行しない。
- [ ] ローカル翻訳選択時はモデルDL後にLlama疎通テストまで完了する。
