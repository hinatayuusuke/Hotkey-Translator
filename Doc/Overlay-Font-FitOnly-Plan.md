# Overlay フォント推定ロジック簡素化（Fit-Only + 安定化）実装案

## 1. 概要（1–3行）
- 後付けの倍率（占有率補正・保守的縮小・折り返しペナルティ等）を撤廃し、**最終表示が枠に収まるか（Fit）**だけでフォントサイズを決める。
- 救済拡張は行わず、**収まるように縮小**する。
- その代わり、**枠の量子化 + ヒステリシス**で揺れを抑える。

## 2. ゴール / 非ゴール
### ゴール
- **常に枠（幅・高さ）を考慮**し、折り返し（表示上の追加改行）込みでテキストが**見切れない**こと。
- ユーザー設定 `OverlayFontSize` を「基準（上限）」として尊重し、必要な場合のみ縮小する。
- 文字が必要以上に小さくならない（縮小は最小限）こと。
- 揺れが目立たないこと（入力/出力の安定化）。

### 非ゴール
- OCR の `LineCount` / `LineHeight` を使った見た目補正（撤廃対象）。
- 「常に同じ見た目サイズにする」ための多段スケーリング。
- 表示の都合で改行を挿入する等、テキスト内容の改変（折り返しは WPF に任せる）。
- 表示専用枠の拡張（救済拡張は行わない）。

## 3. 前提・仮定
- 「表示上の行数」は **最終的にオーバーレイに表示される折り返し込み行数**（WPF の計測結果）。
- オーバーレイのテキストは `TextWrapping=Wrap` で表示される。
- `Rect` は OCR の検出枠であり、**救済拡張はしない**。

## 4. 現状整理
- `UI/OverlayWindow.xaml.cs` ではフォントサイズ推定に以下が混在している。
  - OCR 行高さ補正
  - 画面占有率補正
  - 「大きすぎ」回避の保守的縮小
  - 折り返しが OCR 行数を超えた場合の追加ペナルティ
  - 収まり判定（Fits）と二分探索（Fit）
- ルールが積み上がり、調整の意図・優先順位が把握しづらい。

## 5. 提案アーキテクチャ
### 5.1 コア方針（Fit-Only）
- 入力: `text`, `baseRect`, `baseFont`, `minFont`, `maxFont`, `padding`
- 出力: `fontSize`

決定規則は 2段だけにする。
1) **フォントは基準サイズを上限**として、枠に収まる最大値を選ぶ
   - `fontSize = min(baseFont, FitMaxFont(text, displayRect))`
2) `minFont` でも収まらない場合は **さらに縮小してでも収める**
   - 救済拡張は行わない

### 5.2 揺れ対策（入力 / 出力の安定化）
- **入力の量子化**: `baseRect` の幅/高さを 5px or 10px 単位で丸める
- **出力のヒステリシス**: 変化が小さい場合は更新しない
  - 例: `|newFont - currentFont| < 1.0` なら据え置き
  - 縮小方向は即反映、拡大方向は遅延

## 6. インターフェース設計
### 6.1 整理する関数案
- `ResolveOverlayFontSize(OverlayItem item) -> double`
  - Rect量子化 + FitMaxFont + ヒステリシス

### 6.2 Fit 判定（折り返し込みの実測）
- `Fits(text, fontSize, width, height)` は以下を満たす必要がある。
  - `MaxTextWidth = width`（折り返し発生を計測に反映）
  - `Height <= height`（折り返しで行数が増えた場合に弾ける）

## 7. 実装手順（ステップ分割）
### Step 1: 既存スケールの撤廃（ロジック単純化）
- `GetBaseFontSize()` を簡素化し、`baseFont = clamp(userFont, minFont, maxFont)` のみとする。
- `GetOccupancyScale()` / `GetConservativeScale()` / 折り返しペナルティを削除する。

### Step 2: FitMaxFont（二分探索）を「唯一の縮小機構」にする
- 既存の `Fits()` を利用し、`[minFont .. baseFont]` の範囲で二分探索して最大フォントを求める。
- `FitIterations` は固定小さめ（例: 7）。

### Step 3: 入力/出力の安定化を追加
- **Rect量子化**（5px or 10px刻み）を追加
- **ヒステリシス**（1.0pt閾値）を追加
- 縮小は即反映、拡大は遅延

### Step 4: 例外設計
- どうしても収まらない場合は `minFont` を下回って縮小（例外扱い）

## 8. 非機能要件チェック
### 性能
- 1アイテムあたりの計測回数は概ね `O(fitIterations)` に抑える。

### 可観測性（任意）
- 必要なら `baseFont`, `resolvedFont` をデバッグログ出力。

### 互換性
- 「大きい枠で少ない行が oversized になるのを抑える」系の補正を削除するため、
  一部ケースで以前より文字が大きくなる可能性がある。

## 9. リスクと緩和策
- Risk: ヒステリシスが強すぎると細かい変化が反映されない
  - Mitigation: 閾値は 1.0pt 程度に抑える
- Risk: 量子化が強すぎると細い枠の変化が無視される
  - Mitigation: 5px刻みから試す

## 10. 代替案（最低1つ）と採用理由
- 代替案: 現行の多段補正を維持
  - 不採用理由: 説明可能性と調整容易性が落ちる
- 採用案（本案）: Fit-Only + 安定化
  - 採用理由: 目的（見切れない）を直接満たし、揺れを最小化できる

## 11. 影響範囲（変更ファイル候補）
- `UI/OverlayWindow.xaml.cs`
  - フォント推定ロジックを Fit-Only に置換
  - 量子化 + ヒステリシス導入

## 12. Definition of Done
- 幅が狭く折り返しが増えるケースで、テキストが見切れずに表示される。
- `baseFont` が収まる場合は、基本的に `baseFont` のまま表示される。
- 揺れが目立たず、縮小・拡大の挙動が安定している。
