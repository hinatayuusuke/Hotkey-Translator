# レトロゲーム向け HSV 単一点採色 実装案

## 1. 概要

本実装案は、レトロゲーム向けに簡略化した HSV ベースの OCR 前処理機能を追加するものです。

対象は、字幕色が安定していて色数も少なく、ドット絵に近い描画特性を持つゲームです。ユーザは採色ボタンを押したあと、字幕色を 1 回または 2 回クリックします。アプリ側はそれをもとに内部的な HSV マスクを自動生成し、UI には HSV 微調整項目を出しません。

## 2. ゴール / 非ゴール

### ゴール
- UI をできるだけ簡潔に保つ。
- 画面上の字幕色を直接クリックして設定できるようにする。
- 単色字幕と、文字本体色 + 縁色の両方に対応する。
- 採色結果を内部的な HSV マスクへ自動変換する。
- 1 色または 2 色のマスクを自動判定し、OCR 前処理に使える 1 枚のマスクを生成する。

### 非ゴール
- 初期実装での HSV スライダーによる手動微調整。
- `5x5` や `7x7` の近傍サンプリング。
- シーン全体を対象にした自動色学習やクラスタリング。
- 現代的なアンチエイリアス字幕まで含む汎用色抽出機能。

## 3. 前提・仮定

- 対象は主に、字幕色が安定したレトロゲームである。
- 字幕色はベタ塗りに近く、1 ピクセル採色でも運用可能である。
- 一方で、キャプチャ後の拡大や表示経路の影響で完全な RGB 一致は壊れやすい。
- そのため、UI は 1 ピクセル採色のままにしつつ、内部では小さな固定幅の HSV 許容範囲を使う。

## 4. 現状の課題

- 既存のグレースケール / コントラスト / 二値化だけでは、色付き字幕に弱い場合がある。
- 完全な HSV 手動調整はユーザ負荷が高く、UI も煩雑になる。
- レトロゲーム用途では、単純な採色ベースの方が実用的である。

## 5. 提案アーキテクチャ

### ユーザ向けの操作モデル
- `レトロ字幕色抽出を有効化`
- `字幕色を取得`

ユーザは HSV 数値を直接編集しません。

### 内部モデル
- 1 回目に取得した色を `ColorA` として保存する。
- 2 回目に取得した色を `ColorB` として保存する。
- それぞれの RGB を HSV に変換する。
- 各色に対して固定の内部ルールを適用する。
  - `HueCenter`
  - 小さめの固定 `HueTolerance`
  - `MinSaturation`
  - `MinValue`
- 以下のマスクを生成する。
  - `maskA`
  - 任意で `maskB`
- 最後に必要なら OR 合成する。
  - `finalMask = maskA OR maskB`

### 自動判定ルール
- `ColorB` なし -> 単色抽出
- `ColorB == ColorA` -> 単色抽出
- `ColorB != ColorA` -> 2 色合成抽出

### この構成にする理由
- WHY: ユーザ操作は単純なままにしつつ、内部では完全一致より壊れにくい色抽出にできる。
- WHY: 1 ピクセル採色はレトロゲームの字幕特性に合っている。
- WHY: 最大 2 色のマスク合成で、典型的なレトロゲーム字幕をほぼカバーできる。

## 6. インターフェース設計

### AppSettings 候補
- `EnableRetroColorExtraction: bool`
- `RetroColorSampleA: string` または RGB 構造
- `RetroColorSampleB: string` または RGB 構造

内部で導出する HSV 値は、初期実装ではユーザ編集不要です。

### UI
- チェックボックス: `Enable Retro Color Extraction`
- ボタン: `Pick Subtitle Color`
- 注釈:
  - `Click one color for plain text, or two colors for fill + outline.`
- 必要なら読み取り専用の簡易表示:
  - `Sample 1`
  - `Sample 2`

### 挙動
1. ユーザがレトロ字幕色抽出を有効化する。
2. `Pick Subtitle Color` を押す。
3. アプリは採色待機モードに入る。
4. 1 回目のクリックで `ColorA` を取得する。
5. 必要なら 2 回目のクリックで `ColorB` を取得する。
6. アプリは取得状態から自動判定する。
   - `ColorB` なし -> 単色抽出
   - `ColorB == ColorA` -> 単色抽出
   - `ColorB != ColorA` -> 2 色合成抽出
7. OCR プレビューを即時更新する。

## 7. 内部抽出ルール

### ColorA
- 採色した RGB を HSV に変換する。
- 固定の許容幅を適用する。
  - `HueTolerance`: 完全一致ではなく、小さめ固定値。例: `8..15`
  - `MinSaturation`: 採色値から導出しつつクランプ
  - `MinValue`: 採色値から導出しつつクランプ

### ColorB
- 採色した RGB を HSV に変換する。
- 基本は ColorA と同じ考え方で抽出する。
- ただし 2 色目が黒・白・灰色に近い場合、Hue は不安定になる。
- その場合は Hue よりも Saturation / Value の条件を強めに使う。

### マスク合成
- `finalMask = maskA`
- `ColorB` が有効で、かつ `ColorA` と異なる場合:
  - `finalMask = maskA OR maskB`

### 出力形式
- 条件に一致したピクセルは白
- 不一致ピクセルは黒
- このマスク画像を OCR 前処理結果として扱う

## 8. 前処理順序

推奨順序:

1. レトロ字幕色抽出
2. 必要なら既存の grayscale / contrast / binarization

色抽出時点で十分きれいな白黒マスクになる場合、後段の二値化は不要になる可能性があります。初期実装では安全のため後段処理を残してよいですが、色抽出は必ず先に適用します。

## 9. 実装手順

### Step 1: 設定モデル追加
- 2 色分の採色値と有効フラグを `AppSettings` に追加する。
- 保存形式は単純で明示的なものにする。

### Step 2: UI 追加
- `Enable Retro Color Extraction`
- `Pick Subtitle Color`
- 2 色まで選べる旨の注釈
- 必要なら採色結果の簡易表示

### Step 3: 採色フロー追加
- 既存のターゲット選択 / オーバーレイ入力経路を再利用できるなら再利用する。
- 取得は 1 ピクセルのみとする。
- 1 回目は `ColorA`、2 回目は `ColorB` に保存する。
- 2 回目取得後は自動で採色待機を終了する。
- 1 回のみで終了した場合も `ColorA` 単独で有効とする。

### Step 4: 前処理ステージ追加
- レトロ字幕色抽出ステージを既存の輝度系前処理より前に追加する。
- 保存した RGB を内部 HSV 条件へ変換する。
- `maskA` を生成する。
- 必要なら `maskB` を生成する。
- `ColorB` が `ColorA` と異なる場合のみ OR 合成する。

### Step 5: プレビューとログ
- 採色後に OCR プレビューを更新する。
- ログは簡潔に出す。
  - 採色開始
  - 1 回目 / 2 回目の採色 RGB
  - 導出した HSV 中心値
  - 単色 / 2 色合成の自動判定結果

## 10. 非機能要件

### 性能
- HSV マスク 1〜2 回は OCR に比べて軽い。
- OR 合成のコストも小さい。

### 信頼性
- UI は単純だが、内部は完全一致でなく許容幅付き抽出にする。
- これにより、拡大や表示経路差での微妙な色ずれに耐えやすくする。

### 使いやすさ
- ユーザに HSV の知識を要求しない。
- 操作は採色だけに絞る。

### 互換性
- この機能はレトロゲーム向けの専用モードとして扱う。
- 汎用 OCR 前処理の完全な置き換えは目指さない。

## 11. リスクと緩和策

- Risk: クリックした 1 ピクセルが意図した字幕色ではない。
- Mitigation: 再取得を簡単にし、やり直しコストを低くする。

- Risk: 表示拡大などで実際の色が少しずれる。
- Mitigation: RGB 完全一致ではなく、内部では HSV 許容幅を使う。

- Risk: 2 色目が無彩色寄りで Hue が不安定。
- Mitigation: 低彩度色では Saturation / Value 条件を主に使う。

- Risk: UI 項目が増えて煩雑になる。
- Mitigation: 初期実装では HSV スライダーを一切出さない。

## 13. Definition of Done

- ユーザがレトロ字幕色抽出を有効化できる
- ユーザが字幕色を 1 ピクセルで取得できる
- アプリが内部的に許容幅付きの HSV マスクを自動生成できる
- ユーザが必要なら 2 色目も 1 ピクセルで取得できる
- 2 色目が異なる場合のみ 2 マスクが OR 合成される
- OCR プレビューに結果が反映される
- HSV 微調整 UI は不要

## 14. 推奨 MVP

推奨する最初の実装は以下です。

- 採色ボタンは 1 つだけ
- クリックは最大 2 回まで
- 1 回なら単色抽出
- 2 回で色が異なれば 2 色合成抽出
- 2 回で同色なら単色抽出
- 内部では固定幅の HSV 許容範囲を使う
- 近傍サンプリングは入れない
- HSV スライダー UI は出さない

これにより、UI は簡潔なままにしつつ、レトロゲーム字幕に対しては十分実用的な色抽出を実現できます。
